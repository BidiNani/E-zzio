# E-ZZIO — POLITIQUE DE DÉVELOPPEMENT POST-GOLDEN RELEASE V9.1

## 1. Règle Fondamentale : V9.1 EST EN LECTURE SEULE

À compter du scellement de la Golden Release V9.1 :
- **AUCUNE** modification directe n'est permise sur la baseline V9.1.
- **AUCUN** hot-patch silencieux ne doit être appliqué sur les fichiers certifiés.
- **AUCUNE** mise à jour de dépendances (pip, gradle, npm) ne doit modifier les empreintes de la V9.1.

---

## 2. Cycle Standard de Nouvelle Évolution

Toute nouvelle fonctionnalité, amélioration ou correction doit suivre le schéma de gouvernance suivant :

```text
    ┌───────────────────────────────┐
    │  E-ZZIO V9.1 GOLDEN BASELINE  │ (Lecture seule / Vérité de référence)
    └───────────────┬───────────────┘
                    │
                    ▼  git switch -c feature/<nom>
    ┌───────────────────────────────┐
    │     BRANCHE D'ÉVOLUTION       │ (Développement autonome)
    └───────────────┬───────────────┘
                    │
                    ▼  Implémentation
    ┌───────────────────────────────┐
    │     TESTS & RÉGRESSION        │ (Validation sur 111+ tests)
    └───────────────┬───────────────┘
                    │
                    ▼  Audit Forensique
    ┌───────────────────────────────┐
    │    NOUVELLE CERTIFICATION     │ (V9.1.1, V9.2 ou V10)
    └───────────────┬───────────────┘
                    │
                    ▼  Scellement
    ┌───────────────────────────────┐
    │     NOUVELLE GOLDEN BASE      │
    └───────────────────────────────┘
```

---

## 3. Gestion des Versions

Le versioning suit strictement la nomenclature sémantique E-ZzIO :
- **Patch (V9.1.1)** : Correction de bugs mineurs, ajustements de style UI, compatibilité sans rupture d'API.
- **Minor (V9.2)** : Ajout de nouveaux agents, nouvelles pièces AI Office, intégration de nouveaux providers de modèles locaux.
- **Major (V10.0)** : Évolution architecturale majeure du Frozen Core ou des protocoles de gouvernance HITL.

---
